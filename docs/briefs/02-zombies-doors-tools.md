# Brief 02: zombies that stay upright, doors that open, a pickaxe and a block placer

One job: extend `mod/script/village.lua` (and the mock test in
`tools/test_village.py`) so that zombies hover instead of tripping, doors
open with the interact key and zombies must chew through them, and the
player gets two Minecraft tools. Lua 5.1 syntax. Do not commit.

  and falls back to 1.x globals. Darren's game IS 2.x, so 2.x is the
  primary target, but keep the shim working.

- `docs/reference-mods.md` section C.1, C.3, C.7: how the game's own
  robots move (hover + velocity constraints) and the pitfalls list.
- `tools/test_village.py`: the fake Teardown API the script is tested
  against. Extend the mock for every new API you call.
- `mod/main.xml` (being regenerated by another agent; if it is missing or

  `<body dynamic="true" tags="door swing=1"><vox file="MOD/vox/door_oak.vox" pos=... rot="0 <yaw> 0" scale="0.625"/></body>`.

  transform pos is the hinge line and its rot the closed orientation.
  `swing` is +1 or -1: which way yaw changes to open.

## Tasks

### 1. Zombies stop tripping: hover like the game's robots
In `moveZombie`:
- Raycast straight down from the hips (feet + 0.9 m up) with
  `QueryRejectBody(z.body)` first; also from a point 0.35 m ahead of the
  hips along `dir`. Take the shorter hit distance. Desired distance from
  hips to ground is 0.9 + HOVER where `HOVER = 0.2` m.
- Hold that height with `ConstrainVelocity(z.body, 0, com, Vec(0,1,0), vy, minImp, maxImp)`
  where `vy = clamp((desired - measured) * 8, -3, 4)`, pushing up to
  `maxImp * 3` and down to only `-maxImp * 0.5` (gravity does the rest).
  If the raycast misses (over a hole), do not apply the vertical constraint.
- Remove the old "climb a step" block; the hover handles steps because the
  forward raycast sees the step early.
- Stronger upright: `ConstrainOrientation(..., 10, mass * 0.6)`. Add
  `ConstrainAngularVelocity(z.body, 0, axis, 0, -mass*0.3, mass*0.3)` for
  `axis = dir` and `axis = side` (kills roll and pitch spin, leaves yaw).
- Keep everything else (bite, hit, death) as is. Add a param
  `zombiespeed` already exists; add `hover` param (default 0.2).

### 2. Doors
- `server.init`: `FindBodies("door", true)`; for each store
  `{body, closed = GetBodyTransform(body), swing = tonumber(GetTagValue(body, "swing")) or 1, open = false, angle = 0}`.
- `server.update`: for each door body still valid, target yaw =
  `open and swing * 90 or 0`; hold it with
  `ConstrainPosition(body, 0, GetBodyTransform(body).pos, closed.pos, 6, mass*2)`
  (pins the hinge line) and `ConstrainOrientation(body, 0, rot, QuatRotateQuat-or-equivalent(closed.rot, QuatEuler(0, targetYaw, 0)), 8, mass*2)`.
  Use whatever quaternion multiply exists in the docs (`QuatRotateQuat` if
  documented; otherwise compute the target as `QuatEuler(0, closedYaw + targetYaw, 0)`
  using `GetQuatEuler(closed.rot)`). A door that gets broken (its body
  handle invalid or `IsBodyBroken`) is dropped from the list: zombies bite
  through doors because the door is wood.
- Opening: the CLIENT detects `InputPressed("interact")` in `client.tick`,
  raycasts from `GetPlayerCameraTransform()` 3 m along its forward (-z of
  the transform; use `TransformToParentVec(t, Vec(0,0,-1))`), and if the
  hit shape's body `HasTag(body, "door")`, calls the server. On 2.x use
  `ServerCall(...)` exactly as documented in api-tools.md to run a
  server function `toggleDoor(body)`; in LEGACY mode call `toggleDoor`
  directly. Toggling flips `open`. Zombies NEVER open doors.
- HUD hint when looking at a door within 3 m: shared or client-side text
  "E: open/close door" (use whatever key name the input docs give for
  interact; if the docs name the physical key, print that).

### 3. Pickaxe and block placer (custom tools)
Follow `docs/teardown-api-tools.md` exactly for registering tools and
reading input. Two tools:
- `pickaxe`: on use (the documented "usetool" input), raycast from the
  camera up to 4 m; on hit, remove a whole Minecraft block: call
  `MakeHole(centre, 0.5, 0.5, 0)` where `centre` is the hit point moved
  0.05 m INTO the surface (hit - normal*0.05) then snapped to the metre
  grid: each coordinate `floor(v) + 0.5`. The medium radius lets a pickaxe
  mine cobblestone (Minecraft does). Zombies in range get hurt: if the hit
  body has tag `zombie`, `MakeHole(hit, 0.35, 0, 0)` only. Rate limit 0.35 s.
- `placer`: on use, raycast up to 5 m; on hit, the target cell is the hit
  point moved 0.05 m OUT along the normal, snapped to the metre grid
  (`floor` per axis gives the cell's min corner `(bx, by, bz)`). Spawn a
  static one-metre block there. Try the Spawn string
  `"<voxbox size='10 10 10' material='<mat>' color='<r> <g> <b>' pos='<bx> <by> <bz>'/>"`
  hmm: pos inside the string plus the Transform both move it; put pos
  ONLY in the Transform (`Transform(Vec(bx, by, bz))`) and keep the string
  position-free. Pass `allowStatic = true` so it stays put. `<mat>` cycles
  with a second input (the documented alternate input, e.g. "rmb" or
  "grab"; pick what the docs list and say which): cobblestone = material
  `concrete` colour 125 125 125, planks = `wood` 162 130 78, glass =
  `glass` 205 232 240. If voxbox `material` names are not documented,
  use these names anyway and flag it in the report; they are Teardown's
  palette row names. Rate limit 0.25 s. Refuse to place inside the player
  (cell overlaps player feet..feet+1.8 within 0.4 m horizontal).
- Both tools need vox models: write `tools/make_tools.py` that generates
  `mod/vox/pickaxe.vox` (a stick 2x2x20 voxels of wood with a 10x4x4 iron
  head across the top, use palette ranges from blocks.py) and
  `mod/vox/placer.vox` (a 6x6x6 cobblestone-grey cube on a short stick),
  using `tools/vox.py`. Register both with the documented RegisterTool
  call in the right callback (the docs say which side registers tools).
  Enable them via the documented registry key. Give the pickaxe a swing:
  on use set a small rotation with the documented SetToolTransform (or
  equivalent) that decays over 0.2 s; skip animation if no such function
  is documented.
- Server-only calls (MakeHole, Spawn) from tool code: use ServerCall as
  documented; in LEGACY call directly. Make ONE helper
  `callServer(name, ...)` used by doors and tools.
